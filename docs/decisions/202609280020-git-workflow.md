# 20. Git workflow

Status: Accepted (2026-09-28)

## Context

This is a take-home exercise reviewed as a whole, not a shared codebase with parallel contributors. The
reviewer reads the commit history as the story of the solution. A feature branch and PR would add ceremony
without a second reviewer in the loop, while the author's general rule is "never commit directly to main".

## Chosen

Commit the untouched generated scaffold first, then keep working **on `main`** in small, single-purpose commits
(one plan step each, with lint autocorrect, config, docs and behaviour in separate commits). The user
explicitly overrides the global "no commits to main" rule for this repository.

## Discarded (why)

- **A feature branch and a PR**: ceremony without a second reviewer. The history on `main` is the deliverable.

## Consequences

- The first commit is the generated scaffold, so every later diff shows only deliberate changes.
- Commits are never pushed or rewritten by agents without the user's say-so.
